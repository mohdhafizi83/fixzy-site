Architecture

One engine, four shells.

Your design lives in a stack-neutral intermediate representation. Every shell drives the exact same validated pipeline — no second-class interfaces.

AI-agent-ready

Let your AI build the boring 80%.

Register fixzy mcp once with Claude Desktop or Cursor. The assistant calls the same tools the GUI uses — every step validated, nothing free-written.

claude desktop · fixzy mcp
you: Create a library system: books (title, isbn, stock),
     loans (book_id, borrowed_at). Validate, then generate.

→ fixzy_create_project ✓ Library
→ fixzy_add_table ×2 ✓ books, loans
→ fixzy_add_field ×5 ✓ typed + required
→ fixzy_set_relationship ✓ loans.book_id → books.id
→ fixzy_validate_schema ✓ valid, 0 errors
→ fixzy_generate ✓ 54 files → ~/projects/library
  • Deny-by-default gating — read-only until you pass --allow-write / --allow-generate.
  • PathGuard enforced — output allowlisted; traversal and symlink escapes rejected.
  • Deploy never exposed — touching a live deployment stays a human decision.
  • Same validation as the GUI — the IR gate catches bad schemas before codegen.
What you get

Not a prototype. A shipped system.

One generation pass produces the whole Laravel + Filament application layer:

  • Migrations, models & seeders — with soft deletes, userstamps, indexes
  • Filament resources — lists, forms, detail views, relation managers
  • CSV importers & exporters — with labels and validation
  • Dashboard builder — 12 widget types, live/poll refresh, kiosk mode
  • Auth modules — Google SSO, LDAP/AD, 2FA (TOTP/email), captcha
  • Multi-tenancy — tenant scoping and row ownership
  • Audit trail + activity log — independently selectable
  • Realtime — Reverb or Pusher, live widgets and chat
  • Workflow engine — visual hooks compiling to real PHP observers
  • Deployment guide — engine-aware: SQLite, MySQL, PostgreSQL, Supabase, Neon
